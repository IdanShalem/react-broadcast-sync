Release notes and breaking changes are documented in the repository:

- [CHANGELOG.md](https://github.com/IdanShalem/react-broadcast-sync/blob/main/CHANGELOG.md) - what changed in each release.
- [GitHub Releases](https://github.com/IdanShalem/react-broadcast-sync/releases) - release-by-release notes.

When a release changes behavior you rely on, the changelog entry says how to adapt. The sections of this site describe current behavior; for "what used to be different," the changelog is the source of truth.

## Documentation versions

This site documents **v2** (`>=2.0.0 <3.0.0`), with corrections for the latest reviewed release, **2.2.0**. This is the documentation scope, not a promise of ongoing maintenance for every older minor release.

A major-version label does not mean every API exists in every v2 release. For example, `useSyncedState` requires **2.2.0+**. Check the minimum version on the relevant API page and your installed package version before copying an example.

The site is deployed from `main`. Documentation-only corrections may land after a package release without changing npm. New, unreleased APIs must be explicitly marked as unreleased and must not be presented as available in the latest published package. The version chooser switches between current v2 and the fixed v1.11.2 archive. Search is limited to the selected edition.

## Older and future majors

A [read-only v1.11.2 archive](/v1/) is reconstructed from that release's tagged README, source and types. It is a fixed snapshot of the last v1 release, not coverage of every v1 minor version. The archive corrects misleading historical prose against the tagged implementation and links its original sources.

The version chooser stays on an equivalent page where one exists. Otherwise it opens the archive index at its explanation of missing equivalents. Older-version pages have their own sidebar, search scope and source links. Current demos and v2-only APIs are not presented as v1 content.

Patch releases normally remain within their major's docs with minimum-version notes. A future major or next edition should appear only once it has real, appropriately labelled content. No v3 or unreleased archive is invented here.
